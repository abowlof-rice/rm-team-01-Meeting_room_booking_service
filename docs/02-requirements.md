# REQUIREMENTS
## FR (4-6)  
* FR-1. Сотрудник забронировал комнату, если он не подтверждает присутствие за 5 мин до или после начала брони переговорной, то бронирование пользователя отменяется.  
  
* FR-2. Сотрудник указывает желаемое время брони при поиске, система предлагает ему только свободные в это время комнаты.  
  
* FR-3. Пользователь указывает время брони, превышающее 2 часа, тогда система не даёт осуществить бронь.  
  
* FR-4. Сотруднику, не являющемуся офис-менеджером, не предлагается для брони клиентские комнаты.  
  
* FR-5. Система не создаёт бронь, время которой пересекается с временем существующей брони той же переговорной, в том числе при одновременных запросах.
  
  
## CON (2-3)  
* CON-1. Приложение пишется на Java. Мобильные клиенты — IOS и Android.  

* CON-2. Бюджет — 1,5 млн руб., запуск через 4 месяца.

## EI (1-2)
* EI-1. Макеты интерфейса должны покрывать версию для ПК(1920px), и для планшетов (≈1280px/2560px)
* EI-2. Интерфейс у дверей переговорных работает на планшетах с Android 11+, в браузерах Chrome, FireFox, Safari последних трёх версий
